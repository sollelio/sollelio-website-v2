Method: each bullet checked today against official docs, npm registry metadata, changelogs or pricing pages (source + date/version in parentheses). UNVERIFIED = no primary source found. No recommendations; facts that imply a trade-off are marked "Implication".

## 1. Astro

- **Version:** `astro@7.4.0`, published 2026-10-15 (npm `time`). 7.0.0 = 2026-06-22 (https://astro.build/blog/astro-7/), 6.0.0 = 2026-03-10, 5.7.0 = 2025-04-15.
- **Node:** "v22.22.0 or higher. Odd-numbered versions like v23 are not supported" (https://docs.astro.build/en/install-and-setup/; minimum raised in 7.4.0 release notes).
- **v6 breaking changes** (https://docs.astro.build/en/guides/upgrade-to/v6/): Node 18/20 dropped; Vite 7; Zod 4 from `astro/zod` (`z.email()`); legacy content collections removed; `<ViewTransitions />` and `Astro.glob()` removed; experimental `fonts`, `csp`, `liveContentCollections` stabilised; `i18n.routing.redirectToDefaultLocale` default now `false`; default image service crops by default and never upscales.
- **v7 breaking changes** (https://docs.astro.build/en/guides/upgrade-to/v7/): Vite 8 (Rolldown); Rust compiler only — "Unclosed tags now produce errors", `compressHTML` default `'jsx'` (inline whitespace collapses; use `{" "}`); Markdown via Sätteri — remark/rehype plugins need `@astrojs/markdown-remark` + `unified()`; `@astrojs/db` removed; `src/fetch.ts` reserved.
- **Fonts API — stable, top-level `fonts` array, "Added in astro@6.0.0"** (https://docs.astro.build/en/reference/configuration-reference/). Fields: `provider`, `name`, `cssVariable` (required); `weights` [400], `styles` ["normal","italic"], `subsets` ["latin"], `formats` ["woff2"], `fallbacks` ["sans-serif"], `optimizedFallbacks` true, `display` "swap", `unicodeRange`, `options`. Providers: `fontProviders.local()`, `.google()`, `.fontsource()`, Bunny, Fontshare, Adobe, Google Icons, NPM (https://docs.astro.build/en/guides/fonts/). `import { Font } from "astro:assets"` → `<Font cssVariable="--font-x" preload />` (6.0.0; `preload` accepts `[{weight, style, subset}]`).
- **i18n config** (configuration reference): `locales` (strings or `{path, codes}`), `defaultLocale`, `fallback: Record<string,string>`, `routing` (object | `"manual"`), `routing.prefixDefaultLocale` (default `false`), `routing.redirectToDefaultLocale` (default `false`, only with `prefixDefaultLocale: true`), `routing.fallbackType` (`"redirect"` default | `"rewrite"`, 4.15.0), `domains` (4.3.0; requires `output: "server"` + `@astrojs/node`/`@astrojs/vercel` — not available to a static Netlify site).
- **`astro:i18n` exports** (https://docs.astro.build/en/reference/modules/astro-i18n/): `getRelativeLocaleUrl(locale, path?, opts?)`, `getAbsoluteLocaleUrl`, `getRelativeLocaleUrlList`, `getAbsoluteLocaleUrlList`, `getPathByLocale`, `getLocaleByPath`, `redirectToDefaultLocale`, `redirectToFallback`, `notFound`, `middleware`, `requestHasLocale`, `pathHasLocale`, `toCodes`, `toPaths`. **No `useI18n`.** `Astro.currentLocale` works on prerendered pages; `Astro.preferredLocale` only on on-demand pages.
- **Official recipe** (https://docs.astro.build/en/recipes/i18n/): `src/i18n/ui.ts` with `defaultLang` and `ui` dictionary (`as const`); user-written `getLangFromUrl(url)` and `useTranslations(lang)` → `t(key)` with default-language fallback; optional `routes` map + `useTranslatedPath`. Content: folders `src/content/blog/en/`, `.../pt/`; language from `entry.id.split("/")`; static root redirect via `<meta http-equiv="refresh" content="0;url=/en/" />`.
- **Content Layer** (https://docs.astro.build/en/guides/content-collections/): `src/content.config.ts`; `defineCollection({ loader, schema })`; loaders from `astro/loaders`: `glob({ pattern, base, generateId })`, `file(path, { parser })`; `getCollection(name, ({ id, data }) => …)` (locale filter shown as `id.startsWith('en/')`), `getEntry`, `render(entry)`; entries have `id`, `data`, `body` — **no `slug`**.
- **Images** (https://docs.astro.build/en/guides/images/, …/reference/modules/astro-assets/): `<Image>`/`<Picture>` from `astro:assets`, `alt` mandatory; sharp default (pnpm may need manual install); prerendered pages process at build time; remote sources need `image.domains` or `image.remotePatterns` (`{protocol, hostname, port, pathname}`); `layout`/`fit`/`position`/`priority` props and `image.layout`, `image.responsiveStyles` (default `false`) since 5.10.0, not experimental; `priority` sets loading/decoding/fetchpriority. 7.4.0: `image.service` accepts separate `build`/`runtime` services.
- **Netlify adapter** (`@astrojs/netlify@8.2.10`, 2026-10-15; https://docs.astro.build/en/guides/integrations-guide/netlify/): "For static sites (`output: 'static'`) hosted on Netlify, you usually don't need an adapter." Needed for Netlify Image CDN (`imageCDN` default `true`; "Static sites will need to install this adapter to use and configure Netlify's image service"), Astro `redirects` → `dist/_redirects`, and `staticHeaders`. Netlify docs: "Astro's `<Image />` component automatically uses Netlify Image CDN" (https://docs.netlify.com/build/image-cdn/overview/, 25 Sep 2026). Implication: no adapter = sharp at build time; adapter = request-time transforms on Netlify's CDN.
- **View transitions** (https://docs.astro.build/en/guides/view-transitions/): `<ClientRouter />` from `astro:transitions` is stable, no deprecation; docs say it "will increasingly become unnecessary" as native cross-document transitions mature.
- **TypeScript / `astro check`** (https://docs.astro.build/en/guides/typescript/, CLI reference): presets `astro/tsconfigs/base|strict|strictest`; `include: [".astro/types.d.ts", "**/*"]`; `astro check` exits 1 on errors; recommended `"build": "astro check && astro build"`. Source `packages/astro/src/cli/check/index.ts` (main): needs `@astrojs/check` (0.9.10) and `typescript`; **"astro check does not currently support TypeScript 7.0 … install TypeScript 6 instead … astro check will be deprecated in a future Astro release"**; successor `@astrojs/ts-content-mapper` 0.2.0 (2026-09-22). npm `typescript@latest` = 7.0.2 (2026-07-08); 6.0.3 = 2026-04-16. Implication: pin `typescript@6` for `astro check`.
- **Dev toolbar** (https://docs.astro.build/en/guides/dev-toolbar/): on by default; Audit app runs automatically; disable via `devToolbar: { enabled: false }` or `astro preferences disable devToolbar`. Rules (source `dev-toolbar/apps/audit/rules/`): 24 a11y rules adapted from Svelte (`a11y-missing-attribute`, `a11y-img-redundant-alt`, `a11y-invalid-label`, `a11y-role-has-required-aria-props`, `a11y-media-has-caption`, …) and 6 perf rules (`perf-use-image-component`, `perf-use-loading-lazy`/`-eager`, `perf-use-videos`, slow server render / client hydration). Docs: "not a replacement for dedicated tools like Pa11y or Lighthouse".

Billed as compute. **Scheduled functions**: all plans, cron in UTC (`@hourly`…), 30 s, only on published deploys.
- **Blobs**: "Netlify Blobs (Beta)" on Free/Personal/Pro; object ≤ 5 GB; eventual consistency default (≤ 60 s), `consistency: "strong"` opt-in; `getStore` vs `getDeployStore` (https://docs.netlify.com/build/data-and-storage/netlify-blobs/).

## 7. Core Web Vitals

- **Thresholds** (https://web.dev/articles/lcp, /inp, /cls): LCP good ≤ 2.5 s, poor > 4.0 s; INP good ≤ 200 ms, poor > 500 ms; CLS good ≤ 0.1, poor > 0.25; 75th percentile, mobile/desktop segmented. **INP replaced FID on 12 March 2024** (https://web.dev/blog/inp-cwv-march-12); FID left Search Console that day, other tools after six months.
- **Lighthouse**: 13.5.0 (npm 2026-09-18); 13.0.0 = 2025-10-10; 13.x added Baseline-compatibility audit and an "agentic browsing" category (GitHub releases).
- **`fetchpriority="high"`** (https://web.dev/articles/fetch-priority): `<img src="lcp-image.jpg" fetchpriority="high">`; "a hint, not a directive"; Chrome 102, Edge 102, Firefox 132, Safari 17.2. Astro `<Image priority />` sets it.
- **Font preload** (MDN rel/preload): `<link rel="preload" href="…woff2" as="font" type="font/woff2" crossorigin>` — `crossorigin` required even same-origin; preload "ignores unicode-range declarations" (https://web.dev/articles/font-best-practices). Astro `<Font preload />` emits it.
- **`font-display`** (MDN): `swap` = extremely small block + infinite swap; `optional` = extremely small block, no swap. web.dev: `optional` avoids swap layout shift but may skip the web font; `swap` avoids invisible text; suggested mix: swap for branding, optional for body.
- **Fallback metrics**: `size-adjust`, `ascent-override`, `descent-override`, `line-gap-override` Baseline "widely available" since Sep 2023 (MDN); Astro `optimizedFallbacks: true` (default) generates them.

## 8. Accessibility baseline

- **WCAG 2.2**: W3C Recommendation 5 Oct 2023 (https://www.w3.org/TR/2023/REC-WCAG22-20231005/); current edition 12 Dec 2024 (https://www.w3.org/TR/WCAG22/); 9 new SC, 4.1.1 Parsing removed; new AA: 2.4.11 Focus Not Obscured (Min), 2.5.7 Dragging Movements, 2.5.8 Target Size (Min), 3.3.8 Accessible Authentication (Min); new A: 3.2.6 Consistent Help, 3.3.7 Redundant Entry.
- **EAA — Directive (EU) 2019/882** (Publications Office text, https://publications.europa.eu/resource/celex/32019L0882): Art. 2(2) covers "services provided to consumers after 28 June 2025": (a) electronic communications, (b) access to audiovisual media, (c) passenger-transport elements, (d) consumer banking, (e) e-books, (f) e-commerce services; Art. 3(30) e-commerce = services "at the individual request of a consumer with a view to concluding a consumer contract"; Art. 3(23) microenterprise = < 10 persons and turnover or balance sheet ≤ EUR 2 million; **Art. 4(5): "Microenterprises providing services shall be exempt from complying with the accessibility requirements … and any obligations relating to the compliance with those requirements"**; Art. 2(4) excludes pre-2025 office files/media, third-party content, archives; Art. 32 transition to 28 June 2030.
- **Portugal**: Decreto-Lei n.º 82/2022 (6 Dec 2022) + Portaria 220/2023; applies from 28 June 2025 (MLGTS legal alerts 14 Dec 2022 / 2025). MLGTS footnote on service-provider duties: "Salvo se prestados por microempresas (… menos de dez pessoas … 2 milhões de euros), caso em que estas obrigações não se aplicam." Decree text not retrievable (DRE site script-rendered) — article numbers UNVERIFIED.
- **Cautious reading (verify with lawyer):** a B2B marketing site with an application form, not contracting with consumers, does not obviously fall under any Art. 2(2) category, and a microenterprise providing services is exempt under Art. 4(5). WCAG 2.2 AA (via EN 301 549) remains the technical reference regardless.
